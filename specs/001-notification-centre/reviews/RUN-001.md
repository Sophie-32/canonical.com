## Findings

### F-001: "Complete application" can be marked done while the draft remains unsubmitted

- Reproduction: reset Alex; careers home -> bell -> "Complete application ›" -> "Mark task done" -> back.
- Expected (from task and spec user story 1 #4): the next step continues or submits the Cloud Solutions
  Architect application; "afterward" shows the application as submitted, or the task as still open.
- Actual: the task is recorded as "Done by Alex Morgan", needs-action drops to 0 and the notification
  CTA becomes "View ›", while the workspace and notification still say "has not been submitted yet".
  There is no way to continue the application.
- Evidence: 001a reported it as misleading; 001b and 001c reported success from the "Done" state alone,
  i.e. a false completion on a deadline task. Reproduced by the coordinator (steps 3-5).
- Classification: **product problem** in the prototype's task/state model (task completion detached from
  the application's state; stale copy after completion), compounded by a **missing prototype capability**
  (no simulated application destination). Severity: major (misleading state; a real user would miss the deadline).
- Assumptions: A-008 (read vs completed work) and A-011 (same application throughout) are challenged
  for this action-required case; product D2 holds (read and done are visibly separate), but "done" is
  user-declared rather than following the work.

### F-002: Gemini-reported badge "1" and "Action required" label (not reproduced)

- 001c reported a visible badge "1" contradicting `aria-label` "4 unread", an amber "ACTION REQUIRED" badge,
  an "All (4)" tab and the badge clearing after completion. Reproduction shows badge "4" (then "3"),
  matching the `aria-label`, and no such label or tab count. Classified as **tool/model perception error**.

### F-003: "Demo only" footer visible on the jobseeker destination

- Observed in all runs; 001a found it confusing. It is deliberate prototype scaffolding (product D7 spirit).
  Classified as **missing prototype capability**, superseded in practice by F-001's fix.

### F-004: 501 on cookie-preference POST

- 001a saw console errors after "Accept all". Python's static server rejects POST. **Environment/tool**
  limitation of the snapshot server, not a product finding.
